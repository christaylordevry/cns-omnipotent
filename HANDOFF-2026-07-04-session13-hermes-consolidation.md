## 7. WSL exec gotchas (still true)

- Inline `$(...)` / command substitution to `wsl bash -c "..."` from a Windows-side tool can silently produce empty strings (observed this session getting timestamps via `$(date +%s%3N)` or `$(node -e ...)` inline — worked when run as a separate prior command, failed when chained with `&&` in the same `wsl.exe bash -ic "..."` invocation). Get the value in one call, hardcode it into the next command, rather than chaining substitution across the WSL boundary.
- Node needs nvm on PATH for non-interactive `wsl bash -c` (not `-ic`) invocations — use `wsl.exe bash -ic "..."` (interactive, sources `.bashrc` which sources nvm) rather than `wsl.exe bash -c "..."` when you need `node`/`npm`/`npx` to resolve.
